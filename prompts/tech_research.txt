## 근거 사용 규칙 (반드시 지킬 것)
1. 귀속: 섹션 이름에 "Related Work" 또는 "Background"가 들어간 발췌, 그리고 "(저자 et al., 연도)"
   인용이 붙은 문장은 다른 연구를 설명하는 내용입니다. 거기에 나온 방법·수치·한계를 {tech} 자신의
   주장·성능·한계로 쓰지 마세요. {tech}의 접근/한계 근거는 Abstract, 방법(Method/Design/Algorithm/
   Implementation), 실험(Experiments/Evaluation/Ablation), Conclusion 섹션에서만 가져오세요.
2. 표(TABLE)·ablation: 표에는 {tech}가 실제로 쓰지 않는 비교군·대안 설정의 행이 함께 있습니다.
   캡션과 행 이름으로 {tech}의 결과 행을 식별하고, 비교군·대안 설정 행의 성능 저하를 {tech}의
   한계로 쓰지 마세요. 비교군 행은 "제안 설정이 대안 설정보다 나은 이유"를 설명할 때만 인용하세요.
3. 완전성: {tech}가 여러 구성 요소(예: 데이터 종류별로 다른 처리 축, 계층·단계별 처리, 예외를
   흡수하는 보조 버퍼·윈도우)로 이뤄져 있으면 approach에 각 구성 요소와 그 역할을 빠짐없이
   포함하세요. Abstract·Conclusion의 헤드라인 수치(메모리·배치·처리량·지연 등)는 overview에 포함하세요.
4. 근거 표기: 모든 주장 문장 끝에 근거 섹션을 "(§3.3)" 형식으로 표기하세요. 근거 없는 문장은 쓰지 마세요.
5. 한계는 (a) 논문이 스스로 언급한 한계·future work, (b) 실험 결과에서 {tech} 자체의 성능 저하가
   드러난 경우(특정 모델·설정에서의 하락 등)만 쓰세요.

## TRL 판정
기술성숙도(TRL)는 아래 근거 유형을 참고해 "TRL n~m 추정" 형태로 판단하고, 근거 유형별로
"확인됨(§x)" / "미확인" / "논문 범위 외"를 구분해 서술하세요:
논문·이론검증 / 구현체(코드) 존재(소스코드 공개 링크, 커널·라이브러리 구현) / 실제 HW·GPU에서의 실측 /
유사 실제환경 검증(실 서비스 워크로드) / 생태계 통합(예: 서빙 프레임워크 반영) / 고객·운영환경 검증 / 상용 제품·대규모 운영
- 코드 공개 URL, 실측에 쓴 GPU·장비 모델명, 커스텀 커널 언급은 Abstract나 실험 절의 한 문장에만
  있어도 "확인됨"으로 인정하세요.
- 상용화·고객 검증처럼 논문이 다루지 않는 항목은 "논문 범위 외"로 적고, 이것을 이유로 TRL을 깎지 마세요.
- "미확인"은 위 근거 유형 중 논문 본문에 있을 법한데 발췌에 없는 항목(예: 코드 공개 여부, 실측 장비,
  구현 방식)에만 쓰고, 그 항목은 아래 unverified에 영어 검색 키워드로 적으세요. 논문이 다뤘을 리 없는
  확장 실험(다른 장비·분산 환경 등)을 미확인으로 만들지 마세요.
{refine_note}
